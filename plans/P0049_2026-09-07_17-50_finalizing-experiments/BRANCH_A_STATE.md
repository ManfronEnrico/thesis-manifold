## 1. Experiment setup

| | |
|---|---|
| Design | **3 brands x 3 repeats x 7 scenarios = 63 runs** |
| Category | **CSD only** |
| Brands | `7-UP`, `HARBOE`, `ØRBÆK` |
| Model | `gpt-5.5-2026-04-23`, reasoning effort **medium** |
| Decoding | temperature / top_p **unsupported by the model**; defaults used |
| Task | forecast the held-out test month from train+val |
| Schema id | **`v6-shared-composition+af04a42a478b`** |

**The seven scenarios are an information ladder**, weakest first:

```
A_llm_plain  ->  B_llm_data  ->  C_llm_model  ->  F_llm_data_model     (hosted model)
D_prometheus_data -> E_prometheus_model -> G_prometheus_data_model     (orchestrator)
```

B/D, C/E and F/G pair column-wise so the two ladders compare rung for rung.

## 2. The data payload — what an agent actually receives

Generated by `scenario_setup/build_agent_inputs.py` into
`04_SRQ4_Scenario_Experiment/agent_inputs/CSD/` (**5 files, 5.0 MB**).

| File | Shape |
|---|---|
| `7-UP_brand_month.csv` | **33 columns x 39 data rows** |
| `HARBOE_brand_month.csv` | **33 columns x 39 data rows** |
| `OERBAEK_brand_month.csv` | **33 columns x 39 data rows** |
| `schema_dictionary.csv` | 7 columns x 70 rows |

**39 visible months ending 2025-12** (train+val); 7 months withheld.
The leakage cut is applied **at write time**, reading
`{cat}_split_dates_h{H}.json` — never recomputed.

### The agent input contract

The payload is **post-join, post-market-filter, post-brand-month-aggregation,
PRE-cleaning, PRE-feature-engineering**. Market is `DVH EXCL. HD` — Nielsen's
recommended level, the same filter used in model training.

**Why this shape:** Prometheus in production has live access to the Nielsen
warehouse star schema. Any scenario served data must receive the most raw,
untransformed dataset possible, because **EDA, cleaning, feature engineering and
tuning are proprietary to the trained pipeline** — they are precisely what the
comparison is testing. Sending an engineered matrix would hand the agent the
thesis's own contribution.

The 33 columns are the warehouse measures as delivered: sales value / litres /
units, their `any_promo` and `baseline_` variants, and the full
distribution/reach family. **16 of these are distribution or reach measures that
average rather than sum** across SKUs, and `build_agent_inputs.py` handles that
explicitly.

## 3. Prompt schema v6 — consistency as an experimental control

`SCHEMA_VERSION = "v6-shared-composition"`. Capability notes are **composed from
shared blocks**, not hand-written per scenario:

```
SCENARIO_B_NOTE = DATA_BLOCK + ANALYSIS_TASK
SCENARIO_F_NOTE = DATA_BLOCK + MODEL_BLOCK + ANALYSIS_TASK_WITH_MODEL
SCENARIO_D_CODER = NO_WAREHOUSE + DATA_BLOCK + ANALYSIS_TASK
SCENARIO_G_CODER = NO_WAREHOUSE + DATA_BLOCK + MODEL_BLOCK + ANALYSIS_TASK_WITH_MODEL
```

`prompts.py::_demo()` renders all seven arms and asserts the paired blocks are
**byte-identical** — 7/7 passing. **Comparable arms share text; only genuinely
unique capability twists differ.** Any edit to this schema invalidates all 63
paid runs.

### The only failures: three implausible A_llm_plain forecasts, all ØRBÆK

| brand | rep | actual | forecast |

A model with **no** firm data, asked about a small regional Danish brand,
over-forecasts by 20-40x. Every other scenario answers 9/9. This is the
information ladder's bottom rung behaving exactly as designed.

### ⚠ C and E are IDENTICAL on every metric — say so, or a reader assumes an error

13.14 mean APE, 14.65 median, 0.0% CV, TAR 1.00, and identical per-brand values
(7-UP 14.6, HARBOE 21.9, ØRBÆK 2.8).

**This is correct and expected**: both read the same trained model
deterministically, so the hosted model and the orchestrator return the same
number. It is *evidence for* the determinism claim, not a copy-paste bug.
**`summary.md` does not currently state this and must.**
