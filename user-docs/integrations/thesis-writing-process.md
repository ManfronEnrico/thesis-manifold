# The thesis writing process

Three tools, three different jobs. The failure mode is using one for another's job — the
most expensive version being NotebookLM inventing a citation that Zotero never held.

| Tool | Its one job | Never use it for |
|---|---|---|
| **Zotero** | The single source of truth for what we cite | Deciding whether a claim is true |
| **NotebookLM** | Checking whether a source says what we say it says | Discovering sources, or generating prose |
| **Max's thesis** | A worked example of *structure* at Saunders-compliant length | Evidence for any claim — it is not a citable source |

**The rule that ties them together:** a citation enters the thesis through Zotero, gets
verified through NotebookLM, and is written up by hand. No step may be skipped, and the
order never reverses.

---

## 1. The submission chain — where everything must end up

The chain is **Zotero → Word field codes → submitted .docx**, and it constrains
everything upstream.

```
Zotero group library 6479832          (86 items, live)
   |
   |  zotero_client.py  (python -m utility_scripts.scripts.zotero_client)
   v
05_thesis_writing/citations/bibtex.bib + citations.json
   |
   |  Zotero Word plugin, Add/Edit Citation
   v
05_thesis_writing/sections-final/*.docx   <- what CBS receives
```

### The Word half

Citations go into Word through the **Zotero plugin**, not typed by hand. Each one is a
live field code, so the bibliography regenerates when a source changes. Two consequences
worth internalising now rather than at submission:

- **Add the source to Zotero first.** A citation typed manually is not a field code, will
  not appear in the bibliography, and is invisible to the plugin. This is the single most
  common way a reference goes missing at submission.
- **Do not "Unlink Citations" until the very final export.** It converts every field to
  plain text permanently. Keep a linked master; unlink only a throwaway copy if a
  submission portal demands it.

### The markdown half

Chapters are drafted as markdown in `sections-drafts/`, converted to `sections-final/*.docx`.
The markdown reference lists (e.g. Ch2's 42 entries) are a **working convenience**, not the
submission artefact — the real bibliography is generated by the Zotero plugin in Word.

This is why the standing rule matters: *reference-list entries regenerate from Zotero
automatically; only in-text citations need manual correction.* When a verification round
finds a wrong citation, fix the in-text claim. Do not hand-edit the bibliography.

## 2. Zotero — the gate every source passes through

**Current state (verified 2026-08-25):** 86 items live — 48 journal articles, 21 preprints,
10 conference papers, 3 webpages, 2 books, 2 book sections.

### Refreshing the citation files

```powershell
.venv\Scripts\python.exe -m utility_scripts.scripts.zotero_client
```

Writes `05_thesis_writing/citations/bibtex.bib` and `citations.json`. Run it after adding
papers. Run it **as a module** (`-m`), not as a script path — as a script, repo root is not
on `sys.path` and the import fails.

> Two path bugs were fixed on 2026-08-25: the client looked for `.env` in
> `utility_scripts/` and wrote output to `utility_scripts/docs/literature/`, both
> pre-restructure paths. If either error reappears, the cause is a `parents[1]` that should
> be `parents[2]`.

### Adding a paper — the only approved route

1. Find it (journal page, arXiv, DOI)
2. Save via the **Zotero Chrome connector** from the publisher page — this captures correct
   metadata, which typing does not
3. Download the PDF and rename it to the standard pattern
4. Re-run the client above
5. Cite in Word via the plugin

**The filename rule:** PDF filenames are authoritative metadata, because each was captured
deliberately through Zotero. The exception is anything under a `to_sort-*` folder. This is
why auto-import is forbidden — see §3.

## 3. NotebookLM — verification, not discovery

**Working setup (as of 2026-08-25):** CLI `notebooklm-py`, pinned at **0.8.1** in
`requirements.lock`.

> **If it reports "Authentication expired" — suspect the version first.** On 2026-08-25 the
> installed 0.3.4 had `notebooklm.google.com` hardcoded; Google had migrated to
> `notebook.google.com`. Every call returned an auth error with perfectly valid cookies.
> Upgrading fixed it. Also note `notebooklm auth check` reports "valid" when cookies merely
> *exist* — the honest test is a real call: `notebooklm list`.

Re-authenticating (must run in a real terminal — the `!` prefix aborts at the prompt):

```powershell
.venv\Scripts\python.exe -m notebooklm login
```

Sign in, wait for the homepage, then **return to the terminal and press ENTER**. That
keypress is what writes `~/.notebooklm/storage_state.json`. If that file's timestamp is
unchanged, the login did not save regardless of what the browser showed.

### The notebook

`NLM - Master Thesis - Final Notebook` (`03b4f55a`) — **140 sources**, all ready: 120 PDFs
and 20 markdown files, including all 14 Saunders chapters.

Two things to know about it:

- **15 titles are duplicated**, affecting 30 sources. Harmless for retrieval, but it means a
  source count is not a paper count.
- **Ch3 and Ch4 drafts are not in it.** They must be uploaded before the methodology run —
  a verification question cannot compare against a chapter the notebook cannot see.

### What it is good at

Asking *"does the cited source say what we say it says?"* over a fixed corpus. This is a
closed test: determinate answer, no new source can change it. It found five Contradicted
claims across 37 in the literature round, including the ≤15% accuracy target that did not
exist in Ceran and had propagated into Ch6, Ch9 and Ch10.

Useful commands:

```powershell
# upload a chapter draft
... -m notebooklm source add "05_thesis_writing\sections-drafts\ch3-methodology.md" -n 03b4f55a

# ask, with machine-readable citations and the answer filed as a note
... -m notebooklm ask -n 03b4f55a "<question>" --json --save-as-note

# restrict a question to specific sources
... -m notebooklm ask -n 03b4f55a -s <source-id> "<question>"
```

`--json` returns source IDs per inline citation — real provenance, which is what makes a
verdict checkable rather than a claim about a claim.

**Do not pass `--new`** unless you intend to delete the existing conversation. It prompts
for confirmation and destroys the thread's history.

### What it must not be used for

- **`source add-research --import-all`.** It searches the web and imports results wholesale,
  bypassing Zotero entirely. That breaks the filename-metadata rule, puts unvetted sources
  in the corpus whose discipline is the reason the audits work, and contradicts the standing
  decision to add few papers. If a genuine gap survives, download that one paper through
  Zotero.
- **Generating prose.** See §5.
- **Anything load-bearing at short notice.** It drives the web UI with session cookies, not
  a supported API. It broke once already this month via a domain migration. Fine for a
  bounded review; never a dependency in the submission path.

### What verification structurally cannot find

| Not covered | Why |
|---|---|
| Claims with **no** citation | Nothing to check against — a wrong uncited sentence passes silently |
| Whether a **better** source exists | The corpus is the universe of the test |
| Whether an argument is **complete** | It checks the links present, not the ones missing |
| Whether the **framing** is right | A perfectly-sourced paragraph can answer the wrong question |

That gap is the job of the improvement round —
`notebookLM/00-REVIEW-METHOD-and-improvement-questions.md` — which asks a different question
and collects `corpus gap` answers into **one batch decision**, not a paper per question.

## 4. Max's thesis — a structural model, never a source

Located at `05_thesis_writing/thesis_inspiration/`, and also present in the Final Notebook
(source 76). Different research design and purpose, but closely follows Saunders.

**Read it for form, never for evidence:**

- How many pages each chapter got, and what that implies for balance
- How the research onion was narrated rather than merely listed
- Where methodology detail sat versus appendices — directly relevant to §6
- How findings were presented before being discussed

**The category error to avoid.** If Max's prose sits in the same retrieval pool as Saunders,
a question like *"what does Saunders say about embedded case studies?"* can return **Max's
reading of Saunders** presented as Saunders. That is exactly the failure class this whole
exercise exists to catch.

**Therefore: a separate notebook for structural questions.** Since he is already in the
Final Notebook, either scope questions with `-s` to the Saunders sources, or ask structural
questions in their own notebook. Never cite him.

## 5. Writing a chapter — the loop

```
bullets  ->  approval  ->  prose  ->  verify  ->  Word
```

1. **Bullets first.** Never prose without explicit approval — bullets are reversible, prose
   loses nuance when rewritten.
2. **Approval.** Yours, explicitly.
3. **Prose**, by hand, in `sections-drafts/`.
4. **Verify** via a NotebookLM round once a chapter is substantially drafted.
5. **Apply corrections in one pass per chapter** — Ch3 has ten known repo fixes (S1–S10)
   *plus* whatever the Saunders run returns. Editing twice risks the second pass fighting
   the first.
6. **Convert to `sections-final/*.docx`**, insert citations via the Zotero plugin.

### On "Safest thesis-ready wording"

NotebookLM ends each verdict with a suggested replacement. **Take the facts verbatim;
rewrite the argument yourself.**

The facts — definitions, page-anchored terminology, exact distinctions — are the source's
and you have no licence to vary them. The *argument* is different: those blocks cannot see
what the surrounding sentences need the corrected sentence to do.

The Goodwin case is the precedent. Its suggestion reported the negative finding accurately
and stopped — but that sentence was load-bearing for the entire uncertainty-communication
design. Pasting it would have left a correct sentence sitting in a hole where an argument
used to be. The applied fix reported the finding *and* turned it into an argument for the
interpretive layer, which is stronger than what the thesis had before.

Related: the claim that this makes a thesis "pre-defended against critique" overstates it.
Verification makes claims **accurate**. It does not make an argument **good**, and an
examiner attacks the argument.

## 6. The 120-page target — the honest position

**Measured 2026-08-25: 33,842 words across all drafts.**

At a CBS-typical ~450 words per formatted page (12pt, 1.5 spacing, with figures and
headings), that is roughly **75 pages** — against a 120-page target. The gap is real and
should drive planning, not be discovered in the final week.

| Chapter | Words | Reading |
|---|---:|---|
| ch2-literature-review | 7,603 | Mature — verified, corrections applied |
| ch6-model-benchmark | 6,155 | Mature — verified, fact-checker clean |
| ch4-data-assessment | 4,168 | Solid |
| ch1-introduction | 3,615 | Solid |
| ch3-methodology | 3,504 | **Thin for its role** — carries the whole Saunders design |
| ch5-framework-design | 2,461 | Thin |
| ch8-evaluation | 1,548 | Skeletal — 33 bullet-lines |
| ch7-synthesis | 1,302 | Skeletal — 46 bullet-lines, blocked on results |
| ch9-discussion | 1,274 | Skeletal |
| ch10-conclusion | 946 | Skeletal |

### Where the pages legitimately come from

Ranked by honesty, not ease. **Padding is visible to an examiner** and costs more than the
pages are worth.

1. **Ch7/Ch8 against real results** — the largest genuine gain. Both are bullet skeletons
   because the D/E scenario numbers do not exist yet. Once workstream B lands, these become
   full results chapters. This is real content, not inflation.
2. **Ch3 methodology** — thin for a chapter that must satisfy a Saunders-trained examiner.
   All six onion layers narrated with justification, the reproducibility tiering (core
   scenarios rerunnable, ecological ones NDA-bound), and the three-stage evaluation
   framework. Max's thesis is the calibration reference for how much this deserves.
3. **Ch9 discussion** — currently 1,274 words for the chapter that argues what the results
   *mean*. Limitations, threats to validity, and the negative findings (two of four
   categories beaten by simple benchmarks) deserve full treatment. Examiners reward
   confronting these.
4. **Ch5 framework design** — architecture, design decisions, and the reasoning behind them.
5. **Figures and tables with real captions.** They consume page area legitimately *and*
   improve the thesis. A results table beats a paragraph describing it.

### What does not count

Appendices usually sit **outside** the page count — confirm against
`00_thesis_context/formal-requirements/` before relying on them. Raw logs, full prompt
texts, and code listings belong there regardless, and moving them out of the body may
*reduce* your count while improving the thesis.

**Check the actual requirement.** "120 pages of content" needs a definition: does it include
references, figures, front matter? Confirm this against the CBS guidelines before writing to
the number — writing 20 unnecessary pages is worse than the gap.

## 7. The order of work

1. **Re-auth NotebookLM** if `notebooklm list` fails *(one-off, ~1 min)*
2. **Upload Ch3 + Ch4** to the Final Notebook — they are not in it
3. **Run the methodology verification** — `Methodology_Review-01-HOW-TO-RUN.md`, in blocks
4. **Apply S1–S10 + the run's findings to Ch3/Ch4 in one pass**
5. **Run the improvement rounds** — `00-REVIEW-METHOD-and-improvement-questions.md`
6. **Consolidate every `corpus gap`** into one download decision
7. **Workstream B** (cloud session) produces D/E results
8. **Write Ch7/Ch8 against real numbers**, then verify them
9. **Expand Ch3, Ch9, Ch5** toward target length
10. **Convert to Word, insert Zotero citations, check the page count against the real rule**

Steps 1–6 need no API budget. Step 7 runs in parallel and is the only one that spends money.
